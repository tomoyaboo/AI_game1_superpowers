# S5 到達(ZONE-N→A0-0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** カット割りS5「到達」(Q〜T節、通路爆破〜人間NPCとの対面〜DEMO END)を、デモの最終シーン`4_A00_Demo.unity`で再生される固定演出シーケンスとして実装する。デモ全体の締めくくりであり、このシーンの後にシーン遷移は発生しない。

**Architecture:** `TerminalIntroSequence`(S1)と同じ「固定演出、プレイヤー操作をほぼ介在させない」方針で、単一の新規MonoBehaviour `A00ArrivalSequence` が爆破演出→サイレンス→人間NPC登場→対話→BIOSIGN SCAN/ETA表示→幕切れテキスト→DEMO ENDまでを一直線に進行する。ETA表示は既存の`ObservedValuesHud.FormatEta`/`TimeManager.GetReentryEta()`をそのまま再利用する。新規アートは作れないため、人間NPCは既存`Player`プレファブの流用(色調変更)で表現する。

**Tech Stack:** Unity 2023.1.22f1, C#, NUnit (EditMode), 既存 MessageText / ObservedValuesHud / TimeManager。

**Spec:** `docs/VoidSurvival_カット割り_2.md` (S5節, 701〜814行)

## Global Constraints

- 元のオリジナルシーン・原本アセットは一切変更しない。配置は `Assets/Scenes/Demo/4_A00_Demo.unity` にのみ行う。
- `vendor/VoidSurvival_10-Days/.git` は存在しない(個人リポジトリ内で直接管理)。upstream `NakaAwjr/VoidSurvival_10-Days` には絶対にpush/マージしない。
- 新規C#ファイルは `VoidSurvival.Runtime.asmdef` の対象ディレクトリ(`Assets/VoidSurvival_10-Days/Scripts/`)に置く。
- 既存の`ObservedValuesHud`/`TimeManager`/`MessageText`のAPIは変更せず、読み取りのみ行う。
- イラスト・新規アートは作れないため、人間NPCは既存`Player.prefab`のスプライトを色調変更して流用する。
- `DESCENT READINESS : 2 / 6` はS1で使われている既存の固定値(`DescentReadinessChecklist`のデフォルト項目で完了2件)と同じ値を使う(本編を通して変化しないという前提はカット割り自身の記述と一致する)。

## Review Focus

- `MessageText.Instance`/`TimeManager.Instance`/`ObservedValuesHud.Instance`が未初期化の場合にシーケンスが例外で止まらないこと(既存3シーケンスと同じnullガードパターンを踏襲する)。
- S-7(「誰か説明できる人はいないの」への4秒の無音)とR-8(沈黙)が、他の箇所のように台詞表示や`WaitForSeconds`の短縮と混同されて秒数が削られないこと(演出の原則に「削らない」と明記されている)。
- 白飛び演出(Q-2)の全画面パネルが、シーケンス終了時やDEMO END後に残り続けて他のUIを隠さないこと。
- `A00ArrivalSequence`が二重起動(同一シーン再読み込み等)された場合に、DEMO END演出や台詞が二重に走らないこと(既存の`sequenceStarted`ガードパターンを踏襲する)。
- 人間NPCの`GameObject`がシーン開始時点では非表示で、R-6のタイミングまで見えないこと。

internal static string FormatBiosignScan(int active, int viable, int lost)
